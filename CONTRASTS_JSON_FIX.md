# Contrasts.json Mismatch Fix

## Problem Summary

The report displayed incorrect contrast names because `contrasts.json` had misaligned indices with the actual SPM.mat contrasts:

- **contrasts.json** had 22 entries with indices 1-22 
- **SPM.mat** had 32 contrasts total:
  - Contrasts 1-4: F-contrasts (automatically generated by SPM for ANOVA)
  - Contrasts 5-10: Auto-generated positive effect T-contrasts  
  - **Contrasts 11-32: User-defined T-contrasts** (your actual contrasts of interest)

### The Mismatch

| contrasts.json Index | contrasts.json Name | SPM.mat Actual Contrast at That Index | SPM.mat Type |
|:---:|:---|:---|:---:|
| 5 | G3: T2 - T1 | Positive effect of condition_1 | T |
| 15 | Interaction: (G1 vs G3) trajectory | **G3: T2 - T1** | T |

So when you saw "G3: T2 - T1" in your report, it was actually showing results from contrast #5 ("Positive effect of condition_1") with the wrong label!

## Root Cause

The MATLAB script [`add_contrasts_longitudinal.m`](scripts/utils/add_contrasts_longitudinal.m) was writing contrasts.json with indices 1-22 for the contrasts it generated, but SPM **appends** these to existing contrasts (setting `delete = 0`). The script didn't account for pre-existing contrasts when writing the JSON indices.

## Fixes Applied

### 1. Fixed MATLAB Script (add_contrasts_longitudinal.m)

Changed the script to:
- Reload SPM.mat after appending contrasts
- Write **ALL** contrasts from SPM.xCon to contrasts.json with correct indices
- This ensures contrasts.json always matches SPM.mat

### 2. Fixed Python Script (post_stats_report.py)

Added safety check to:
- Prioritize SPM.mat names over contrasts.json
- Only use contrasts.json for indices not in SPM.mat
- Warn when mismatches are detected

### 3. Fixed Your Current Analysis

Created corrected contrasts.json with all 32 contrasts properly indexed:

```bash
python fix_contrasts_json.py
```

This script:
- Reads SPM.mat directly
- Extracts all contrast names and types
- Creates corrected contrasts.json
- Backs up the old file
